# Изменения

## 0.8.0

- **Безопасность службы и обновлений:**
  - Защита прав доступа к папке программы (`protect_home`) при установке службы (`--install`) стала строго обязательной: при невозможности выставить ACL (или на файловой системе без поддержки ACL, например FAT/exFAT) установка службы откатывается и прерывается с понятной ошибкой, исключая локальное повышение привилегий (EoP).
  - Обновления программы и ядра `mihomo` требуют обязательной проверки контрольной суммы SHA-256 (из метаданных GitHub Release или текста релиза) и проверки заголовка исполняемого файла PE (`MZ` / архитектура `x86_64`) до запуска или замены бинарного файла.
  - В распаковщике архивов обновлений добавлена защита от Zip Slip, дубликатов имён файлов и превышения лимита числа записей.
  - Исправлена паника при разрезании многобайтовых UTF-8 строк по байтовому индексу в парсере конфигураций (`import.rs`) и разборе пути службы (`win.rs`); добавлено жёсткое ограничение (4 МБ) на потоковую распаковку `vpn://` контейнеров Amnezia.
  - Именованный канал IPC (`ipc.rs`) переведён на ограниченную очередь (`mpsc::channel(64)`), лимит параллельных запросов, таймаут выполнения и защиту от флуда мутирующими командами.
- **Защита HTTP на порту 80 без утечки IP:**
  - По умолчанию группа `PLAIN` для нешифрованного трафика TCP/80 при отсутствии собственного сервера и рабочего WARP использует `REJECT` вместо скрытого прямого выхода `DIRECT`, чтобы исключить утечку реального IP-адреса провайдеру. В настройках добавлен явный переключатель «Разрешить прямой выход HTTP (порт 80)» для пользователей, которым нужен доступ к старым HTTP-сайтам напрямую.
- **Исправление шторма проверок маршрутов (`R-__default` / `R-__default-s`) и залипания на мёртвых IP:**
  - Группы маршрутов `R-<id>` переведены в режим `lazy: true` с интервалом 300 с.
  - В `route_health` и `mark_failed` добавлен механизм изоляции сбойных узлов (Circuit Breaker): мёртвые серверы (такие как `95.213.245.84:443`) немедленно помечаются сбойными и вытесняются из `R-__default-s` и пула, прекращая бесконечные ошибки `context deadline exceeded`.
  - Устранены лишние перезагрузки конфигурации (`маршруты применены` / `reload_main`) при каждом обновлении пула бесплатных серверов: `http_policy` теперь идемпотентна относительно ротации пула и обновляет `pool.yaml` без сброса активных соединений.
- **Строгий выбор страны:**
  - Если пользователь выбрал конкретную страну (или несколько стран), `scan::pool` и автовыбор используют только серверы этих стран и никогда скрытно не подключают сервер другой страны. При отсутствии рабочих серверов в выбранной стране выводится честное предупреждение и запускается поиск.
- **Улучшение двухзвенного обхода (`Через входное звено`) и Cloudflare WARP:**
  - В кандидаты для проверки через входное звено (`relay_candidates`) включены серверы, отсеянные из-за таймаутов, сброса соединения ТСПУ (`соединение сброшено` / `соединение закрыто`) и обрыва потока после ~16 КБ.
  - Перед проверкой двухзвенных цепочек лаборатория предварительно прогревает входные узлы и делает повторный проход по резервному тестовому URL.
  - Убрана 3-дневная блокировка WARP после одной неудачи (заменена адаптивным бэкоффом от 15 минут до 4 часов). Если Cloudflare заблокирован напрямую, Лазейка автоматически проверяет WARP через рабочий входной сервер (`VPN → WARP`).
  - Добавлена поддержка ссылок `masque://` (MASQUE / HTTP/3) и реестр легальных бесплатных VPN-провайдеров (`providers.rs`) с классификацией ошибок авторизации (`AuthRequired` никогда не помечает сервер мёртвым), защитой учётных данных на диске (Windows DPAPI / ключ привязки + шифрование с паролем для переноса) и маскированием секретов в логах.
- **Интерфейс и диагностика:**
  - На главном экране отображаются выходной IP, статус защиты от утечек, входное звено (`Через входное звено: …`) и быстрые кнопки выбора страны и запуска поиска.
  - В списке и карточке сервера отображаются маршрут (`Напрямую` / `Через: <узел>`), выходной IP, статус проверки, уровень доверия, лимиты бесплатного тарифа и предупреждение о рисках публичных узлов.
  - В разделе «Маршруты» добавлена сквозная нумерация приоритетов правил (`№ 1`, `№ 2`), а анализатор маршрутов показывает номер приоритета, полную цепочку прохождения по звеньям (`Компьютер → … → Интернет`) и перекрытые правила.
  - В диалоге «Проверка сети» расширена таблица диагностики ТСПУ/DPI (`TCP/443`, `UDP/443`, `Cloudflare`, `DNS`, `Обрыв после 16 КБ`) и добавлена строка «Рекомендуемый транспорт».

## 0.7.0

- Проверка сети в настройках: доступность сайтов и Cloudflare, UDP (STUN, DNS и QUIC), признаки подмены DNS и обрывов загрузки. Результаты — приблизительная диагностика, а не гарантия для каждого адреса и порта. В сети с признаками белых списков соответствующие источники проверяются первыми; при признаках блокировки UDP/Cloudflare часть прямых проверок пропускается.
- При подозрении на обрыв соединения после нескольких килобайт поиск дополнительно проверяет загрузку 160 КБ через сервер. Результат диагностики кэшируется для обнаруженной сети.
- WARP не проверяется напрямую при недоступности Cloudflare; если варианты не проходят, повторная попытка откладывается на три дня. Через включение WARP в настройках можно запустить проверку снова; при заблокированном Cloudflare может помочь цепочка «VPN → WARP».
- Резервный сервер проверяется отдельно от активного (без повторного запуска WireGuard/WARP); при двух неудачах убирается из рабочих. В пуле соседние бесплатные серверы по возможности из разных подсетей и протоколов.
- «Остальной трафик» можно направить через VPN, напрямую, страну, сервер, WARP или цепочку. В выборе цепочек есть шаблоны «VPN → WARP» и, когда WARP уже работает напрямую, «WARP → VPN». Для одного ключа WARP одновременно разрешается одна цепочка; при конфликте с прямым WARP цепочка временно использует обычный VPN.
- Включённая по умолчанию настройка «Защита HTTP на порту 80» отправляет TCP на порт 80 через рабочий свой сервер или WARP, а при их отсутствии — **напрямую с раскрытием IP**, даже при строгой маршрутизации. Это правило не распознаёт HTTP на других портах и не гарантирует, что весь оставшийся трафик зашифрован; настройку можно отключить.
- Для определения адресов серверов добавлен резервный DNS Яндекса.
- Поиск серверов: исправлена главная причина «находит мало» — при заполненной базе (1500) непроверенные серверы из списков вытеснялись и на 21 день попадали на «кладбище», так ни разу и не проверившись. Теперь кандидаты держатся в памяти, в базу попадают только проверенные; лишние рабочие при обрезке откладываются на 2 дня, непроверенные не хоронятся вовсе. Дата первого появления сервера помнится 14 дней.
- Разведчик учится: подсети /24 и SNI рабочих и мёртвых серверов за последние 2 дня задают порядок проверки; лимит кандидатов от источника подстраивается под его долю успеха; все «не ответившие» в каждом батче проверяются ещё раз через запасной тестовый адрес с удвоенным таймаутом; статистика источников со временем «стареет».
- +14 источников серверов (Reality/VLESS/Trojan для России, белые списки CIDR и др.), у всех проверены адреса и зеркала jsDelivr. Списки источников скачиваются через VPN, если туннель уже работает (иначе — напрямую).
- Маршруты: под полем «Сайт или программа: куда отправить?» — кнопки «Напрямую», «Через VPN», «Страна, сервер…», «Блокировать». Запись добавляется в подходящий маршрут (или создаётся новый) и убирается из других. После любой правки маршруты упорядочиваются сами (частные правила выше общих).
- Списки со своим направлением стали маршрутами с подключённым списком; у списка видно, в каких маршрутах он используется.
- Цепочки: новое звено «WARP» (например, «VPN → WARP», если WARP напрямую не работает в вашей сети). В настройках и выборе направления показывается состояние WARP.
- Всплывающие уведомления больше не перехватывают нажатия (раньше кнопки под ними «переставали нажиматься»); уведомление — вверху окна.
- Ссылки: `security=false/0/auto` — без TLS, транспорт `none` — TCP, отбрасывается мусор после `#` в типе транспорта.

## 0.6.1

- Свой WireGuard / AmneziaWG как входное звено: вставьте конфиг (`.conf`, Clash YAML с `type: wireguard`, `vpn://` Amnezia) в «Мои серверы» — пока он проходит проверку, через него (и только через него) проверяются остальные серверы.
- Приоритет звена: свой/избранный сервер → Reality → остальные по оценке. Бесплатные WireGuard-профили и WARP звеном не бывают.
- Серверы, оживающие только через звено, — запасной уровень: в авто-выборе они всегда ниже серверов, работающих напрямую.
- Чистка базы жёстче: сервер мёртв, если ни напрямую, ни через звено не работал 3 дня (ни разу — 2 дня).
